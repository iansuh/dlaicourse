## 1. 준비물

1. **게임 전용 Google 계정(Gmail)** 을 새로 만듭니다. 2단계 인증을 켭니다. 이 계정이 개발자 계정·AdMob의 주인이 됩니다. 이 주소가 공개 "개발자 이메일"과 문의 이메일이 됩니다. 공개 이메일에는 스팸과 악성 메일이 많이 오므로 개인 메일과 꼭 분리하세요.
2. **게임 전용 전화번호**를 준비합니다(본인 명의의 세컨드 번호, 추가 회선 등). 한국 개발자의 개인 계정은 처음부터 이 번호가 스토어에 공개되고, 트레이더도 공개 전화번호가 필요합니다. 문자나 자동 음성 전화로 인증번호를 받을 수 있어야 합니다. 070 인터넷 전화가 되는지는 확인하지 못했으니 직접 시험해 보세요.
3. **본인 명의 해외 결제 카드**(등록비)와 **신분증**(신원 확인용).
4. **Android 10 이상 실제 휴대폰** 한 대(루팅 안 된 것). 새 개인 계정은 Play Console 앱으로 휴대폰 인증을 해야 합니다.
5. **도메인**(권장): 서버 담당에게 연결을 부탁합니다. 개인정보처리방침·약관·계정 삭제 페이지·app-ads.txt가 이 주소로 나갑니다. 실명이 들어가지 않는 주소로 고르세요.
6. **앱 이름 최종 확인**: `STORE_LISTING.md`의 추천안을 휴대폰 Play 스토어에서 검색해 똑같은 이름의 앱이 없는지, KIPRIS(kipris.or.kr)에서 "숫자야구 조용한 한판"을 검색해 상표가 없는지 봅니다.

## 2. 개발자 계정 만들기 (개인 계정, 트레이더)

1. 게임 전용 Google 계정으로 로그인한 상태에서 https://play.google.com/console 에 접속합니다.
2. 계정 유형에서 **개인(Personal)** 을 고릅니다.
3. **개발자 이름**(스토어 맨 위에 보이는 이름): 게임이나 스튜디오 이름(예: `숫자야구 스튜디오` 같은 이름)을 씁니다. 실명은 트레이더 정보에 따로 표시되므로 개발자 이름까지 실명일 필요는 없습니다.
4. **결제 프로필**: 실명과 주소를 넣습니다. **이 주소가 트레이더 주소로 스토어에 공개됩니다.** 신분증과 맞는 실제 법적 주소여야 하며, 남의 주소나 가짜 주소를 쓰면 안 됩니다.
5. **연락처 이메일·연락처 전화번호**: Google이 운영자에게 연락할 때만 쓰는 정보로 공개되지 않습니다.
6. **개발자 이메일(공개)**: 게임 전용 이메일. **개발자 전화번호(공개)**: 게임 전용 번호. 모두 인증번호로 확인합니다.
7. **트레이더 여부 신고**: **"트레이더(trader)"** 를 고릅니다. 광고 수익이 있는 앱은 Google 기준 트레이더입니다. 화면 안내에 따라 공개 전화번호 등을 확인합니다. 이용약관 링크를 물으면 `https://[도메인]/terms` 를 넣습니다.
8. 공개될 정보를 보여 주는 화면이 나오면 이름·주소·전화·이메일이 맞는지 확인합니다.
9. 등록비 25달러를 결제합니다.
10. **신원 확인**: 신분증 사진을 올립니다. 며칠 걸릴 수 있습니다.
11. **휴대폰 인증**: 휴대폰에 "Google Play Console" 앱을 설치하고 같은 계정으로 로그인해 안내대로 인증합니다(1분 정도).
12. 인증이 끝나야 앱을 출시할 수 있습니다.

## 4. 앱 서명: Play 앱 서명 + 업로드 키

### 개념

- **앱 서명 키**: Google이 보관합니다(Play 앱 서명). 새 앱은 자동으로 사용합니다. 사용자 휴대폰에 설치되는 앱은 이 키로 서명됩니다.
- **업로드 키**: 우리가 만들어 보관합니다. 앱 파일(AAB)을 Play에 올릴 때 "우리가 올린 게 맞다"는 증명입니다. 잃어버려도 Google에 재설정을 요청할 수 있지만 며칠 걸립니다.

### 업로드 키 만들기

`keytool`은 Android Studio에 들어 있습니다.

- Windows: `C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe`
- macOS: `/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool`

명령 창(Windows는 PowerShell, macOS는 터미널)에서 **저장소 폴더가 아닌 곳**(예: 바탕화면의 새 폴더)으로 이동한 뒤 실행합니다. 한 줄입니다.

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=NumberBaseball, O=NumberBaseball, C=KR"
```

- 비밀번호를 두 번 물어봅니다. 길고 무작위인 비밀번호(20자 이상)를 쓰고 **비밀번호 관리자**에 저장하세요.
- `-dname` 에는 게임 이름만 넣었습니다. 업로드 키 인증서는 이용자에게 배포되지 않지만, 굳이 실명을 넣을 필요는 없습니다.
- `upload-keystore.jks` 파일이 생깁니다.

확인과 인증서 내보내기(재설정 요청이나 기록용):

```bash
keytool -list -v -keystore upload-keystore.jks -alias upload
keytool -export -rfc -keystore upload-keystore.jks -alias upload -file upload_certificate.pem
```

`upload_certificate.pem` 은 공개돼도 괜찮은 인증서입니다. `.jks` 파일과 비밀번호는 절대 공개하면 안 됩니다.

### 안전하게 보관하기

1. **GitHub 저장소에 절대 올리지 않습니다.** (저장소의 `.gitignore`가 `*.jks`, `*.keystore`를 막고 있지만, 애초에 저장소 폴더 안에 두지 마세요.)
2. 채팅, 이메일, 스크린샷으로 보내지 않습니다.
3. 백업 2곳: 예) 비밀번호 관리자의 파일 첨부 + 암호 걸린 USB. 비밀번호는 파일과 다른 곳에 둡니다.
4. **GitHub Actions 비밀값**으로 자동 빌드에 넘깁니다. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret. 이름은 Android 담당이 `.github/` 설정에 맞춰 알려 줍니다. 보통 이런 4개입니다.

| 비밀값 이름 (예시) | 값 |
| --- | --- |
| `UPLOAD_KEYSTORE_BASE64` | `.jks` 파일을 글자로 바꾼 값 (아래 명령) |
| `UPLOAD_KEYSTORE_PASSWORD` | 키 저장소 비밀번호 |
| `UPLOAD_KEY_ALIAS` | `upload` |
| `UPLOAD_KEY_PASSWORD` | 키 비밀번호 (보통 같은 값) |

`.jks`를 글자로 바꾸는 명령:

```bash
# macOS (결과가 클립보드에 복사됨)
base64 -i upload-keystore.jks | pbcopy
# Linux
base64 -w 0 upload-keystore.jks
# Windows PowerShell (결과가 클립보드에 복사됨)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks")) | Set-Clipboard
```

광고 단위 ID도 같은 방법으로 비밀값에 넣습니다(9장).

### 업로드 키를 잃어버렸다면

Play Console → 해당 앱 → **앱 무결성(App integrity) → Play 앱 서명** → **업로드 키 재설정 요청**. 새 키를 만들고 `upload_certificate.pem`(새 키에서 내보낸 것)을 올립니다. 계정 소유자만 요청할 수 있고 며칠 걸립니다.

- 앱 이름, 간단한 설명, 자세한 설명: `STORE_LISTING.md`의 en-US를 붙여 넣고, **번역 추가**로 나머지 9개 언어(ko-KR, ja-JP, zh-CN, es-419, fr-FR, de-DE, pt-BR, ru-RU, vi)를 넣습니다.

### 5-3. 콘텐츠 등급 (IARC 설문)

- 이메일: 게임 전용 이메일. 카테고리: **게임**.
- 폭력, 공포, 성적 내용, 도박, 약물, 저속한 유머: 모두 **아니요**.
- **사용자 간 상호작용 또는 콘텐츠 교환: 예** (채팅이 있으므로).

## 9. AdMob 설정 (광고)

### 9-1. 계정 만들기

1. 게임 전용 Google 계정으로 https://admob.google.com 접속 → 가입.
2. 국가: **대한민국** (나중에 못 바꿈).
3. 계정 유형: **개인** (D안이면 조직). 나중에 못 바꿈.
4. 결제 정보의 이름: **신분증·통장과 똑같은 실명**. 주소: 우편을 받을 수 있는 주소(PIN 우편이 옵니다). 이 정보는 스토어에 공개되지 않습니다.
5. 전화번호 인증.

**AdMob이 요구하는 개인정보**: 실명, 우편 주소, 전화번호, 신분증(수익이 10달러에 도달하면 확인 요청, 45일 안에 제출), 은행 계좌, 세금 정보. 이 중 스토어나 앱에 공개되는 것은 없습니다. 단 하나, Google의 공개 목록(sellers.json)에 이름이 나갈 수 있는 설정이 있는데 기본값은 **비공개(기밀)** 입니다. **절대 "공개"로 바꾸지 마세요**(나중에 되돌려도 공개됐던 기록이 남을 수 있음).

### 9-2. 앱과 광고 단위 만들기

1. **앱 → 앱 추가 → Android** → "앱이 스토어에 등록되어 있나요?" → 아직이면 **아니요** → 앱 이름 `Number Baseball: Quiet Duel`(스토어 이름과 같게).
2. **앱 ID**(`ca-app-pub-...~...` 형태)를 받아 Android 담당에게 전달합니다.
3. **광고 단위 만들기** 2개:
   - 배너 1개 (이름 예: `home_results_banner`)
   - 전면 광고 1개 (이름 예: `vs_computer_interstitial`)
   - 보상형 광고는 만들지 않습니다.
4. 광고 단위 ID 2개(`ca-app-pub-.../...`)를 **GitHub Actions 비밀값**(예: `ADMOB_APP_ID`, `ADMOB_BANNER_ID`, `ADMOB_INTERSTITIAL_ID`)에 넣습니다. 저장소 파일에는 넣지 않습니다.
5. 개발 중에는 Google의 **테스트 광고 ID**만 씁니다(Android 담당이 처리).
6. **본인이나 지인이 실제 광고를 누르면 안 됩니다.** 부정 클릭으로 계정이 정지될 수 있습니다. 광고를 누르라고 부탁하는 문구도 금지입니다.
7. **차단 관리**에서 도박, 데이트, 술, 성인 관련, 일확천금류 등 민감한 광고 카테고리를 차단합니다. 청소년도 쓰는 앱이므로 꼭 하세요.
8. **광고 콘텐츠 등급 상한**은 콘텐츠 등급(IARC) 결과에 맞춥니다. 전체이용가(3+, Everyone)면 **G**, 7+/E10+면 **PG**, 12+/Teen이면 **T**. 앱 등급보다 높은 광고를 보이면 Play 정책 위반입니다. 등급이 나오면 Android 담당에게 알려 주세요(앱 설정값으로 들어갑니다).
9. **미성년자 광고 보호**: 앱은 처음 실행할 때 나이를 묻고, 만 14~15세에게는 맞춤형 광고와 광고 ID 전송을 끄고, 만 16~17세에게는 Google 청소년 보호를 적용합니다(Android 담당이 구현). 만 14세 미만은 앱을 쓸 수 없습니다.

### 9-3. 동의 메시지 (개인정보 보호 및 메시지)

AdMob → **개인정보 보호 및 메시지**:

1. **유럽 규정 메시지(GDPR)** 만들기: 언어 10개 선택, 개인정보처리방침 URL `https://[도메인]/privacy`, 앱 선택 → 게시. (유럽경제지역·영국·스위스 이용자에게 필요합니다.)
2. **미국 주 규정 메시지** 만들기: 같은 방식으로 게시.
3. 앱은 이 메시지를 UMP로 띄우고, 설정에 "개인정보 옵션" 메뉴를 둡니다(Android 담당).

### 9-4. 출시 후: 스토어 연결과 app-ads.txt

1. 앱이 Play에 공개되면 AdMob → 앱 → **앱 설정 → 앱 스토어 세부정보 추가**에서 Play 스토어 앱을 연결합니다.
2. AdMob → 앱 → **app-ads.txt** 메뉴에서 한 줄을 복사합니다. 모양은 이렇습니다.
   ```text
   google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0
   ```
3. 서버(예: Render)의 **Environment**에 `APP_ADS_TXT` 라는 이름으로 그 한 줄을 넣고 저장합니다(서버 담당이 만든 기능).
4. 브라우저로 `https://[도메인]/app-ads.txt` 를 열어 그 줄이 보이는지 확인합니다.
5. Play Console의 **스토어 설정 → 웹사이트**가 같은 도메인인지 확인합니다.
6. 하루 이상 기다리면 AdMob의 app-ads.txt 상태가 "확인됨"으로 바뀝니다. 앱이 공개된 뒤에만 확인됩니다.
7. AdMob이 앱을 검토 중이라는 표시가 있으면 끝날 때까지 광고가 적게 나올 수 있습니다.

### 9-5. 세금 정보와 돈 받기

1. AdMob → **결제 → 설정 → 세금 정보 관리 → 미국 세금 정보 추가**: 개인 → 미국인이 아님.
   - 미국 안에서 하는 활동이 없다면 **"미국 내 활동이 없는 해외 게시자"** 진술에 동의하는 방법이 있습니다(양식 없음).
   - 한미 조세조약 혜택을 받으려면 AdMob은 개인에게 W-8BEN이 아니라 **Form 8233**을 안내합니다.
   - 어느 쪽이 맞는지는 **세무사에게 확인**하세요. 정보가 틀리면 미국 수익분에서 최대 30%가 원천징수될 수 있습니다.
2. 수익이 10달러가 되면 **신원 확인**(신분증), 이어서 **PIN 우편**이 옵니다(2~3주). 4개월 안에 AdMob에 PIN을 입력합니다.
3. **지급 기준액 100달러**. 넘으면 다음 달 말쯤 등록한 은행 계좌로 해외 송금됩니다(은행 영문명, SWIFT 코드 필요).
4. 광고 수익은 한국 종합소득세 신고 대상일 수 있습니다. 세무사에게 확인하세요.
5. 현실적인 기대치: 하루 100명이 하면 한 달 10달러 안팎, 1,000명이면 한 달 수십~100달러 정도로 추정됩니다(외부 통계 기준, 크게 달라질 수 있음). 서버비를 메우는 정도로 생각하세요.
