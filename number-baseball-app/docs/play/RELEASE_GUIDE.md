## 0. 전체 흐름과 비용


## 1. 준비물

1. **게임 전용 Google 계정(Gmail)** 을 새로 만듭니다. 2단계 인증을 켭니다. 이 계정이 개발자 계정·AdMob의 주인이 됩니다. 이 주소가 공개 "개발자 이메일"과 문의 이메일이 됩니다. 공개 이메일에는 스팸과 악성 메일이 많이 오므로 개인 메일과 꼭 분리하세요.
2. **게임 전용 전화번호**를 준비합니다(본인 명의의 세컨드 번호, 추가 회선 등). 한국 개발자의 개인 계정은 처음부터 이 번호가 스토어에 공개되고, 트레이더도 공개 전화번호가 필요합니다. 문자나 자동 음성 전화로 인증번호를 받을 수 있어야 합니다. 070 인터넷 전화가 되는지는 확인하지 못했으니 직접 시험해 보세요.
3. **본인 명의 해외 결제 카드**(등록비)와 **신분증**(신원 확인용).
   - 광고 제거를 팔 때는 **본인 명의 은행 계좌**(판매 대금을 받는 곳)와 세금 정보도 필요합니다(10장). 한국 개인이 인앱 상품을 팔 때 **사업자등록·통신판매업 신고 정보**를 요구하는지 확인하지 못했으니, 10-1을 먼저 읽고 세무사에게 물어보세요.
4. **Android 10 이상 실제 휴대폰** 한 대(루팅 안 된 것). 새 개인 계정은 Play Console 앱으로 휴대폰 인증을 해야 합니다.
5. **도메인**(권장): 서버 담당에게 연결을 부탁합니다. 개인정보처리방침·약관·계정 삭제 페이지·app-ads.txt가 이 주소로 나갑니다. 실명이 들어가지 않는 주소로 고르세요.
6. **앱 이름 최종 확인**: `STORE_LISTING.md`의 추천안을 휴대폰 Play 스토어에서 검색해 똑같은 이름의 앱이 없는지, KIPRIS(kipris.or.kr)에서 "숫자야구 조용한 한판"을 검색해 상표가 없는지 봅니다.

## 2. 개발자 계정 만들기 (개인 계정, 트레이더)

1. 게임 전용 Google 계정으로 로그인한 상태에서 https://play.google.com/console 에 접속합니다.
2. 계정 유형에서 **개인(Personal)** 을 고릅니다.
3. **개발자 이름**(스토어 맨 위에 보이는 이름): 게임이나 스튜디오 이름(예: `숫자야구 스튜디오` 같은 이름)을 씁니다. 실명은 트레이더 정보에 따로 표시되므로 개발자 이름까지 실명일 필요는 없습니다.
4. **결제 프로필**: 실명과 주소를 넣습니다. **이 주소가 트레이더 주소로 스토어에 공개됩니다.** 신분증과 맞는 실제 법적 주소여야 하며, 남의 주소나 가짜 주소를 쓰면 안 됩니다.
5. **연락처 이메일·연락처 전화번호**: Google이 운영자에게 연락할 때만 쓰는 정보로 공개되지 않습니다.
6. **개발자 이메일(공개)**: 게임 전용 이메일. **개발자 전화번호(공개)**: 게임 전용 번호. 모두 인증번호로 확인합니다.
7. **트레이더 여부 신고**: **"트레이더(trader)"** 를 고릅니다. 광고 수익이 있는 앱은 Google 기준 트레이더입니다. 화면 안내에 따라 공개 전화번호 등을 확인합니다. 이용약관 링크를 물으면 `https://[도메인]/terms` 를 넣습니다.
8. 공개될 정보를 보여 주는 화면이 나오면 이름·주소·전화·이메일이 맞는지 확인합니다.
9. 등록비 25달러를 결제합니다.
10. **신원 확인**: 신분증 사진을 올립니다. 며칠 걸릴 수 있습니다.
11. **휴대폰 인증**: 휴대폰에 "Google Play Console" 앱을 설치하고 같은 계정으로 로그인해 안내대로 인증합니다(1분 정도).
12. 인증이 끝나야 앱을 출시할 수 있습니다.

## 4. 앱 서명: Play 앱 서명 + 업로드 키

### 개념

- **앱 서명 키**: Google이 보관합니다(Play 앱 서명). 새 앱은 자동으로 사용합니다. 사용자 휴대폰에 설치되는 앱은 이 키로 서명됩니다.
- **업로드 키**: 우리가 만들어 보관합니다. 앱 파일(AAB)을 Play에 올릴 때 "우리가 올린 게 맞다"는 증명입니다. 잃어버려도 Google에 재설정을 요청할 수 있지만 며칠 걸립니다.

### 업로드 키 만들기

`keytool`은 Android Studio에 들어 있습니다.

- Windows: `C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe`
- macOS: `/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool`

명령 창(Windows는 PowerShell, macOS는 터미널)에서 **저장소 폴더가 아닌 곳**(예: 바탕화면의 새 폴더)으로 이동한 뒤 실행합니다. 한 줄입니다.

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=NumberBaseball, O=NumberBaseball, C=KR"
```

- 비밀번호를 두 번 물어봅니다. 길고 무작위인 비밀번호(20자 이상)를 쓰고 **비밀번호 관리자**에 저장하세요.
- `-dname` 에는 게임 이름만 넣었습니다. 업로드 키 인증서는 이용자에게 배포되지 않지만, 굳이 실명을 넣을 필요는 없습니다.
- `upload-keystore.jks` 파일이 생깁니다.

확인과 인증서 내보내기(재설정 요청이나 기록용):

```bash
keytool -list -v -keystore upload-keystore.jks -alias upload
keytool -export -rfc -keystore upload-keystore.jks -alias upload -file upload_certificate.pem
```

`upload_certificate.pem` 은 공개돼도 괜찮은 인증서입니다. `.jks` 파일과 비밀번호는 절대 공개하면 안 됩니다.

### 안전하게 보관하기

1. **GitHub 저장소에 절대 올리지 않습니다.** (저장소의 `.gitignore`가 `*.jks`, `*.keystore`를 막고 있지만, 애초에 저장소 폴더 안에 두지 마세요.)
2. 채팅, 이메일, 스크린샷으로 보내지 않습니다.
3. 백업 2곳: 예) 비밀번호 관리자의 파일 첨부 + 암호 걸린 USB. 비밀번호는 파일과 다른 곳에 둡니다.
4. **GitHub Actions 비밀값**으로 자동 빌드에 넘깁니다. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret. 이름은 Android 담당이 `.github/` 설정에 맞춰 알려 줍니다. 보통 이런 4개입니다.

| 비밀값 이름 (예시) | 값 |
| --- | --- |
| `UPLOAD_KEYSTORE_BASE64` | `.jks` 파일을 글자로 바꾼 값 (아래 명령) |
| `UPLOAD_KEYSTORE_PASSWORD` | 키 저장소 비밀번호 |
| `UPLOAD_KEY_ALIAS` | `upload` |
| `UPLOAD_KEY_PASSWORD` | 키 비밀번호 (보통 같은 값) |

`.jks`를 글자로 바꾸는 명령:

```bash
# macOS (결과가 클립보드에 복사됨)
base64 -i upload-keystore.jks | pbcopy
# Linux
base64 -w 0 upload-keystore.jks
# Windows PowerShell (결과가 클립보드에 복사됨)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks")) | Set-Clipboard
```

광고 단위 ID도 같은 방법으로 비밀값에 넣습니다(9장).

### 업로드 키를 잃어버렸다면

Play Console → 해당 앱 → **앱 무결성(App integrity) → Play 앱 서명** → **업로드 키 재설정 요청**. 새 키를 만들고 `upload_certificate.pem`(새 키에서 내보낸 것)을 올립니다. 계정 소유자만 요청할 수 있고 며칠 걸립니다.

## 5. Play Console 양식 하나씩 채우기

### 5-1. 스토어 등록정보 (기본 스토어 등록정보)

- 앱 이름, 간단한 설명, 자세한 설명: `STORE_LISTING.md`의 en-US를 붙여 넣고, **번역 추가**로 나머지 9개 언어(ko-KR, ja-JP, zh-CN, es-419, fr-FR, de-DE, pt-BR, ru-RU, vi)를 넣습니다.
- 그래픽: 아이콘 512×512 PNG, 그래픽 이미지 1024×500, 휴대폰 스크린샷 6장(디자인 담당이 준비). 광고가 보이는 화면이나 실제 플레이어 닉네임은 넣지 않습니다.
- 앱 카테고리: 게임 → **보드** 또는 **퍼즐**(둘 중 하나, 추천: 퍼즐). 태그는 관련 있는 것만.
- **스토어 설정 → 연락처 세부정보**: 이메일 = 게임 전용 이메일, 웹사이트 = `https://[도메인]`, 전화번호 = 비워 둠(선택 사항). **웹사이트 칸은 app-ads.txt 때문에 꼭 넣습니다.**

### 5-2. 앱 콘텐츠 (정책 → 앱 콘텐츠)

| 양식 | 답 |
| --- | --- |

## 9. AdMob 설정 (광고)

### 9-1. 계정 만들기

1. 게임 전용 Google 계정으로 https://admob.google.com 접속 → 가입.
2. 국가: **대한민국** (나중에 못 바꿈).
3. 계정 유형: **개인** (D안이면 조직). 나중에 못 바꿈.
4. 결제 정보의 이름: **신분증·통장과 똑같은 실명**. 주소: 우편을 받을 수 있는 주소(PIN 우편이 옵니다). 이 정보는 스토어에 공개되지 않습니다.
5. 전화번호 인증.

**AdMob이 요구하는 개인정보**: 실명, 우편 주소, 전화번호, 신분증(수익이 10달러에 도달하면 확인 요청, 45일 안에 제출), 은행 계좌, 세금 정보. 이 중 스토어나 앱에 공개되는 것은 없습니다. 단 하나, Google의 공개 목록(sellers.json)에 이름이 나갈 수 있는 설정이 있는데 기본값은 **비공개(기밀)** 입니다. **절대 "공개"로 바꾸지 마세요**(나중에 되돌려도 공개됐던 기록이 남을 수 있음).

### 9-2. 앱과 광고 단위 만들기

1. **앱 → 앱 추가 → Android** → "앱이 스토어에 등록되어 있나요?" → 아직이면 **아니요** → 앱 이름 `Number Baseball: Quiet Duel`(스토어 이름과 같게).
2. **앱 ID**(`ca-app-pub-...~...` 형태)를 받아 Android 담당에게 전달합니다.
3. **광고 단위 만들기** 2개:
   - 배너 1개 (이름 예: `home_results_banner`)
   - 전면 광고 1개 (이름 예: `match_end_interstitial`, 컴퓨터·온라인 대결 뒤에 함께 씁니다)
   - 보상형 광고는 만들지 않습니다.
4. 광고 단위 ID 2개(`ca-app-pub-.../...`)를 **GitHub Actions 비밀값**(예: `ADMOB_APP_ID`, `ADMOB_BANNER_ID`, `ADMOB_INTERSTITIAL_ID`)에 넣습니다. 저장소 파일에는 넣지 않습니다.
5. 개발 중에는 Google의 **테스트 광고 ID**만 씁니다(Android 담당이 처리).
6. **광고를 산 사람에게는 광고 요청 자체가 없어집니다**(앱이 처리). 테스트할 때는 광고 제거 상품을 산 계정과 안 산 계정을 모두 써 봅니다.

## 10. 광고 제거 상품 만들기 (Google Play 결제)

**한 줄 요약:** 앱 안의 "광고 제거"를 **한 번만 사면 모든 광고가 사라지는** 상품(`remove_ads`, 4.99달러)입니다. 결제와 환불은 모두 Google Play가 처리하고, 우리 서버는 관여하지 않습니다. 컴퓨터(PC)의 Play Console 웹 화면에서 하는 것이 쉽고, 휴대폰 Play Console 앱에서는 일부 메뉴가 없을 수 있습니다. 메뉴 이름은 가끔 바뀌니 비슷한 이름을 찾으세요.

### 10-1. 먼저 확인할 것 (판매자 설정)

1. **결제 프로필을 "판매용"으로 설정**합니다. Play Console → **설정 → 개발자 계정 → 결제 프로필** (또는 **수익 창출 설정**/Monetization setup). 광고만 있을 때는 필요 없었지만, 앱 안에서 물건을 팔면 Google이 판매자(merchant) 정보를 요구합니다.
   - 실명, 주소(이미 트레이더로 공개되는 주소와 같게), **정산받을 은행 계좌**(본인 명의, 해외 송금이 되는 계좌와 영문 이름·SWIFT 코드), **세금 정보**.
   - 주소와 이름은 이미 트레이더로 공개되므로 **새로 공개되는 것은 없습니다.**
2. **한국 개인 개발자는 사업자등록·통신판매업 신고 정보를 요구받을 수 있습니다.** 저는 이 요구가 개인 계정에도 적용되는지 확인하지 못했습니다(`POLICY_CHECKLIST.md` 12절). **상품을 만들기 전에** 위 결제 프로필 화면에 사업자 정보 입력 칸이 나오는지 확인하고, 나오면 **세무사에게 개인사업자(통신판매업) 등록을 물어보세요.** 막히면 1.0은 광고만으로 출시하고, 등록이 끝난 뒤 업데이트로 `remove_ads`를 여는 방법도 있습니다(앱은 구매 화면만 숨기면 됩니다. Android 담당과 상의).
3. **앱이 먼저 올라가 있어야 합니다.** Play 결제 기능이 든 앱 파일(AAB)을 **내부 테스트**에 한 번 올린 뒤에야 상품 만들기가 열리는 경우가 많습니다. 7장을 먼저 진행하세요. (Android 담당에게 "Play 결제 라이브러리가 들어간 AAB"인지 확인.)

### 10-2. 상품 만들기

1. Play Console → 앱 선택 → **수익 창출 → 제품 → 앱 내 상품** (영문: **Monetize with Play → Products → In-app products**). 최근 Google이 "일회성 제품(One-time products)" 방식으로 바꿔 가는 중이라 이름이 **일회성 제품 → 일회성 제품 만들기**일 수 있습니다. 같은 것입니다.
2. **제품 ID**: `remove_ads` 를 **정확히** 입력합니다(소문자와 밑줄). **한 번 만들면 바꾸거나 다시 쓸 수 없습니다.** Android 담당이 앱에 같은 글자로 넣어 두었는지 확인하세요.
3. **이름**과 **설명**(언어별로 추가). 아래 값을 그대로 붙여 넣으세요.

| 언어 | 이름 (55자 이내) | 설명 (200자 이내) |
| --- | --- | --- |
| 한국어 (기본으로 두는 언어) | `광고 제거` | `모든 광고를 없앱니다. 한 번만 결제하면 같은 Google 계정으로 계속 적용됩니다.` |
| English (en-US) | `Remove ads` | `Removes all ads. One-time purchase that stays with your Google account.` |

   기본 언어가 영어이면 영어를 기본으로 하고 한국어를 "번역 추가"로 넣습니다. 다른 8개 언어는 비워 두면 기본 언어로 보입니다(원하면 `STORE_LISTING.md` 방식으로 나중에 번역).
4. **구매 유형**: **일회성 구매 / 구매(Buy)**, 즉 **소모성이 아닌(non-consumable) 1회 상품**입니다. 소모품이나 **구독으로 만들지 마세요.** 새 화면에서 "구매 옵션 ID"를 물으면 `buy` 처럼 짧게 넣고 Android 담당에게 알려 줍니다(앱이 어떤 ID를 쓰는지 확인).
5. **가격**
   1. **기본 가격**: **4.99 USD** 를 입력합니다.
   2. **다른 나라 가격**: **"가격 템플릿 적용"** 또는 **"환율로 가격 변환(Convert prices / Update prices)"** 을 누르면 Google이 나라별 현지 가격을 자동으로 채웁니다(한국은 약 6,500원으로 나옵니다). 가격 템플릿(Price templates) 메뉴가 있으면 한 번 만들어 두면 다음 상품에도 쓸 수 있습니다.
   3. **나라별 가격 한 번 훑어보기**: 한국이 6,500원 안팎인지, 이상하게 비싸거나 싼 나라가 없는지 봅니다. 이상한 나라는 직접 고칠 수 있습니다. 부가세 포함 표시는 Google이 나라 규칙대로 처리합니다.
6. **사용 가능 국가**: 앱 출시 국가와 같게 전체로 둡니다.
7. **저장 → 활성화(Activate)**. **활성(Active)** 상태여야 앱에서 보입니다. 비활성이면 앱이 가격을 못 가져옵니다.
8. 활성화 뒤 몇 분~몇 시간 걸려야 앱에 반영될 수 있습니다.

### 10-3. 테스트 구매 (돈이 나가지 않게)

1. Play Console 왼쪽 위 **설정**(또는 계정 전체 화면의 **설정**) → **라이선스 테스트**(License testing). 계정 전체 메뉴라 앱 안이 아니라 맨 처음 화면의 설정에 있습니다.
2. **라이선스 테스터**에 테스트에 쓸 Gmail 주소를 넣습니다(본인 것 포함). **라이선스 응답**은 "RESPOND_NORMALLY"(기본)로 둡니다. 저장.
3. 그 Gmail 계정을 **내부 테스트 테스터 목록(7-1)** 에도 넣고, 참여 링크로 앱을 **Play 스토어에서 설치**합니다(직접 설치한 APK로는 구매가 안 됩니다).
4. 앱의 설정 → 광고 제거를 눌러 구매합니다. 결제창에 **"테스트 카드, 항상 승인"** 같은 선택지가 나오고, **실제로 돈이 나가지 않습니다**.
5. 확인할 것: 광고가 바로 사라짐 / 앱을 지웠다 다시 깔아도(같은 계정) 광고 없음 / 설정의 **구매 복원**이 동작 / 테스트 결제를 **환불**하면(Play Console → 주문 관리) 앱을 다시 열 때 광고가 돌아옴 / 주문 관리에서 구매가 "확인(acknowledged)" 상태.
6. 라이선스 테스터가 아닌 사람은 **실제로 결제됩니다.** 테스트는 반드시 위 목록의 계정으로 하세요.

### 10-4. 어디에 무엇을 표시하나 (광고와 앱 내 구매)

| 표시 | 어디서 | 어떻게 |
| --- | --- | --- |
| **광고 포함 (Contains ads)** | Play Console → 정책 → **앱 콘텐츠 → 광고** | **예, 광고가 포함되어 있습니다.** 광고 제거 구매가 있어도 "예" |
| **앱 내 구매 제공 (In-app purchases)** | 양식 없음. **자동 표시** | 10-2에서 `remove_ads` 를 **활성**으로 만들고 그 앱 버전이 올라가면 스토어에 붙습니다. 스토어 등록정보 미리보기에서 확인 |
| 구매 내역 수집 | **앱 콘텐츠 → 데이터 보안** (5-4) | 금융 정보 → 구매 내역: 수집, 공유 안 함, 선택, 앱 기능 |
| 디지털 상품 구매 | **콘텐츠 등급 설문** (5-3) | 예 |
| 개인정보·약관 | `/privacy` 7-1절, `/terms` 7절 | 이미 반영됨. 대괄호만 채우기 |

### 10-5. 환불과 문의 응대

- **환불은 Google Play가 처리**합니다. 이용자는 Google Play 앱의 구매 내역에서 요청하고, 운영자가 따로 할 일은 없습니다(운영자가 직접 환불할 수도 있음: Play Console → **주문 관리**).
- 이메일로 "환불해 주세요"가 오면: "Google Play 앱 → 프로필 → 결제 및 정기 결제 → 예산 및 내역(구매 내역)에서 요청해 주세요"라고 안내하고, 필요하면 주문 관리에서 환불합니다.
- "계정을 지웠는데 광고가 다시 나와요" → "같은 Google 계정으로 앱을 깔고 설정 → **구매 복원**을 눌러 주세요. 구매는 Google 계정에 남아 있습니다."
- "새 휴대폰에서 광고가 나와요" → 같은 Google 계정인지 확인, 구매 복원.
- 서버가 구매를 확인하지 않아서, 구매 내역 조회·복구는 Google Play 쪽에서만 가능합니다.

## 11. 출시 후 할 일

- **신고 확인 매일 1번 이상**(서버 관리 기능). 24시간 안에 조치하는 것이 목표, 늦어도 3일. 아동 관련 신고는 즉시 계정 정지 후 관계 기관에 신고.
- 게임 전용 이메일 매일 확인(이용자 문의, Google 정책 메일).
- **이메일 계정 삭제 요청 처리**: ① 받은 `닉네임#태그`를 관리 기능에서 찾습니다. ② 이메일을 받은 뒤에도 그 계정이 앱에서 쓰였다면 삭제하지 말고 "앱의 설정 → 계정 삭제를 이용해 주세요"라고 답장합니다(남의 계정을 지우려는 요청 방지). ③ 아니면 7일 안에 삭제하고 "삭제했습니다"라고 답장합니다. ④ 요청 이메일은 처리 후 30일이 지나면 지웁니다.
- Play Console의 **정책 상태**와 받은편지함 확인. 경고가 오면 기한 안에 고칩니다.
- 해마다 8월 말 전에 **목표 API 수준** 업데이트(2027년에는 API 37이 예상되지만 아직 공식 발표 전).
- 트레이더 신고는 계정 설정에서 상태를 확인(2027-02-01 기한, 신규 계정은 가입 때 신고).
- 앱 기능이나 SDK가 바뀌면 데이터 보안 양식, 개인정보처리방침, 콘텐츠 등급을 다시 확인.
- 채팅 같은 소셜 기능을 바꾸는 업데이트 전에는 릴리스 담당과 상의하세요. 미국 텍사스 법 때문에 "중요한 변경"이면 Google Play에 알려야 할 수 있습니다. **빠른 대결 자유 채팅(`QUICK_MATCH_FREE_CHAT`)은 청소년이 이용하는 동안 켜지 마세요.**
- 트레이더라서 공개된 주소·전화로 연락이 올 수 있습니다. 위협이나 괴롭힘은 기록을 남기고 경찰에 신고하세요.
- 개발자 계정을 오래 쓰지 않으면 휴면으로 닫힐 수 있으니 1년에 몇 번은 업데이트나 로그인을 합니다.
