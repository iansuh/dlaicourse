# Phase 2 design review: Android renders

Reviewer: design lead. Date: 2026-11-25. Build: commit `5d883d9` ("phase 2 designed UI for every screen … 290 reference renders").

Scope: the 290 Roborazzi renders in `android/app/screenshots/`, set against `design/shots/` (48 reference shots), `DESIGN_SYSTEM.md`, `tokens.json`, `screens/*.md` (including FLOW and ADAPTIVE) and `README.md`. I opened every pair (reference | render | diff) and the extra states, small-window (360 × 320) and 200 % font variants as images. Positions and colours were measured with PIL at density 2 (2 px = 1 dp). Every sampled flat colour was checked against `tokens.json`, including alpha tokens composited over the surfaces. The Compose source was read only to name the cause and the file to fix. App code was not changed.

## Verdict

**Not signed off.**

At 1.0 font scale on a 360 × 800 phone the build is close to the reference. Geometry is mostly within 0.5 dp: keypad, slots, log rows, ad band and dock. Every flat colour is a token. Three things still block sign-off:

1. **200 % font breaks the match screen** and loses game data (D2-01). The 1.3× cap for numerals in fixed controls is not implemented anywhere, and neither is the large-text layout from ADAPTIVE §2.
2. **Small window and 200 % layouts collapse whole regions:** lobby teams, team result, and the result line score (D2-02, D2-03, D2-04, D2-26).
3. **Specified features are missing without a documented deviation:** team-board best hints, profile tables, interactive tutorial, the transposed large-memo sheet, and transfer-code entry hidden under the IME (D2-13, D2-15, D2-16, D2-17, D2-34). There are also touch targets under 48 dp (D2-09, D2-10).

Counts: **1 blocker, 18 major, 17 minor** (36 defects).

## What could not be compared

- **de / ru (9 reference shots):** `home-de`, `home-ru`, `lobby-de`, `lobby-ru`, `match-guess-de`, `match-guess-ru`, `match-small-de`, `result-lose-de` (and `icon-preview`, which is not a screen). The app ships only `values/` (en) and `values-ko/`, so these cannot be rendered. See D2-30.
- **Status bar and gesture pill:** these are drawn by the test frame and were ignored. The 24 dp insets are real and correct.
- **Sample ad creative (`#D9DCD4`, `#3A3F3B`):** test only (`LocalAdPreview`). Excluded from the colour audit.
- **Result shots `result-win-ko/en`:** the reference page overflowed, so the reference ad band sits 10 dp lower and only 14 dp above the screen bottom. The render places it correctly at y = 725 dp with the 24 dp inset below it, as DESIGN_SYSTEM 13 requires. The reference shot is wrong here, not the app.
